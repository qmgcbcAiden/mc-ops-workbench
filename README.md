## 项目概览

MC 运维工作台是一款帮助新手管理 Minecraft Java 服务器的本地运维工具，可使用桌面窗口，也可切换到默认仅供本机访问的 Web 模式。

如果你只是想和朋友联机，却被 Java 版本、启动脚本、黑色命令行、报错日志和各种配置文件劝退，这个项目就是为你准备的。

你可以在一个界面里启动和关闭服务器、查看谁在线、观察电脑占用、阅读日志、管理玩家和修改常用设置。遇到看不懂的报错时，可以让 AI 结合相关日志给出解释；配置 AI 后，游戏内玩家也可以通过 `@AI` 获得简短答疑。

AI 不是必需品。即使不配置任何 AI，也可以正常使用大部分服务器管理功能。

### 面向新手

项目重点解决“想和朋友联机，但不会开服、不会看日志”的问题，不以专业商业服主面板为目标。

服务器启停、Java 检测、日志查看、玩家管理和配置编辑都尽量通过可理解的界面完成。

### 本地能力优先

确定性的服务器操作由本地 Python 服务完成。AI 只负责理解自然语言、解释问题和调用预先注册的受控工具。

AI 查询的是实际服务器状态，不会只根据聊天上下文猜测在线玩家、运行状态或配置内容。

### 安全与恢复

高风险命令需要用户确认，明显不是 Minecraft 命令的内容会被拒绝。

配置修改支持差异审查、审计记录、版本历史和回滚。Mod / 插件诊断也会优先依据本地元数据、依赖关系和运行日志。

### 为什么做这个项目

**启动门槛**

新手常常不知道该安装哪个 Java，也看不懂启动脚本窗口一闪而过后的错误。

传统开服要求用户同时理解命令行、配置文件、端口和服务端日志，这对只想和朋友联机的人来说过于复杂。

**日常管理**

人数、难度、正版验证、管理员权限和封禁等常见操作分散在配置文件与命令中，输入错误还可能影响服务器运行。

工作台希望把这些操作放在同一个界面中，并在容易出错的位置提供提示、确认和记录。

**扩展与排错**

Mod 或插件的版本、加载器和依赖不匹配，往往最终只表现为“服务器打不开”。

项目会尽量从本地文件和日志中寻找证据，再给出具体说明，而不是单纯让模型猜测。

### 适合谁

- 第一次尝试开服，或只想和朋友搭建小型服务器的 Minecraft 玩家。

- 已有服务端文件，但不熟悉命令行、Java、日志和配置文件的个人服主。

- 预算有限，希望使用自己的电脑运行 Minecraft Java 服务器的学生或个人用户。

### 它是什么

这是一个运行在用户自己电脑上的服务器工作台，提供启停、启动脚本、玩家、监控、日志、命令和配置管理能力。

它也是一个可选的 AI 辅助工具，可以解释日志、生成受控配置提案、诊断 Mod / 插件问题，并为游戏内玩家提供受限短对话。

### 它不是什么

- 不是 Pterodactyl 等成熟托管面板的替代品，也不是多节点集群管理系统。

- 不是服务器租赁或全自动托管平台。

- 不能自动解决所有 Mod / 插件冲突。

目前项目仍处于早期版本，主要用于管理本机上的一个 Minecraft Java 服务器。仓库不会提供 `server.jar`、Mod、插件或其他服务端程序，你仍需自行获取并遵守对应许可。

## 功能特性

### 服务器控制

- 通过按钮启动、停止或重启服务器，并查看状态、PID、在线人数、CPU 和内存占用。

- 自动识别当前平台可用的 Shell、Batch 等 Minecraft 启动脚本；没有脚本时生成受管理的启动脚本。

- 启动时确保使用 `nogui`。需要改写简单脚本时先备份，无法安全处理复杂脚本时取消启动并说明原因。

### Java 环境

应用会结合服务端信息判断所需 Java 版本，并优先使用已有环境。

找不到合适版本时，可以按设置下载项目内独立的 Temurin Java，不必替换系统 Java。

### 玩家与命令

- 查看在线玩家、管理员和封禁名单，处理 OP、封禁、解封等常见操作。

- 所有命令都经过本地风险策略；高风险操作需要明确确认，阻止的内容不会执行。

- 命令请求及执行结果会进入本地审计记录。

### 日志能力

- 实时读取服务器日志，并支持搜索和等级筛选。

- 将相关日志片段交给 AI，解释可能原因和处理方向，而不是上传整份日志。

- 通过日志和运行状态辅助识别启动失败、组件加载错误及其他常见问题。

### 文件工作台

- 浏览和编辑服务端允许修改的配置、文本及启动脚本。

- 为支持的格式提供语法高亮和保守格式化。

- 限制访问范围与文件类型，避免工作台读取或修改服务端目录之外的内容。

### 配置管理

- 重要配置修改支持差异审查、修改记录、版本历史和回滚。

- 默认先展示配置提案的风险、原因和 diff，由用户确认后再写入。

- 自主配置循环需要单独启用，并受到轮次、调用次数和自动应用风险阈值限制。

### 运维 AI 助手

- 可以用自然语言查询在线玩家、服务器状态、日志和安全配置快照。

- 支持生成配置提案和受控服务器操作；最终执行仍由本地策略决定。

- 内置 DeepSeek、Qwen 配置，也可添加提供 OpenAI 兼容接口的服务商，并动态获取可用模型。

### 游戏内 `@AI`

配置好模型服务并启用游戏内 AI 后，玩家可以直接输入 `@AI 这个附魔有什么用？`。应用会从服务器日志识别请求，生成短回复，再由受控命令通道发回游戏。

游戏内 AI 只用于闲聊、游戏机制答疑和简短建议，不会执行服务器命令、修改配置或处理运维操作。

每位玩家使用独立且有长度、时效、冷却和队列限制的短上下文。管理员可以关闭功能、限制为仅管理员可用，或通过名单规则调整访问权限。

### Mod / 插件扫描

- 扫描 `mods/*.jar` 和 `plugins/*.jar`，读取可识别的名称、版本、加载器和依赖信息。

- 判断 Mod 与插件是否放错目录，以及组件类型是否与 Fabric、Forge、NeoForge、Paper 等服务端匹配。

- 发现重复组件、多个版本同时存在等本地安装问题。

### 依赖与兼容性

- 查找组件声明中缺少的必需依赖。

- 根据本地信息以及可选的 Modrinth / CurseForge 元数据检查 Minecraft 版本兼容性。

- 从日志中识别插件加载失败、Mixin 错误、缺少类、缺少方法和依赖异常。

### 诊断边界

诊断结果会标明证据来自本地元数据、依赖关系、在线元数据还是运行日志，并给出建议动作。

当前版本只生成修复草案，不会直接删除、移动、禁用、替换或修改 jar 文件。诊断不可能覆盖所有整合包与插件组合，处理文件前仍应做好备份。

### 为什么不是简单套壳

- 没有 AI 也能完成服务器启停、玩家查询、监控、日志查看、文件编辑和命令执行。

- AI 只能使用项目注册的工具，不能自行运行系统命令、访问任意文件或决定操作风险。

- 游戏内 AI 使用独立的受限提示词，不具备运维权限；模型调用和工具操作均保留审计记录。

## 架构与技术

### 工作原理

```text
UI (Flet)
    |
    v
Interface
    |
    v
Service -------------------+
    |                       |
    v                       |
Repository                  |
    |                       |
    v                       |
SQLite                      |
                            |
AI Assistant -> Tool Registry
                    |
                    +------> Service
```

### 分层职责

- **UI / Interface**：UI 只负责展示和交互，Interface 为界面提供稳定的轻量调用门面。

- **Service / Repository**：Service 承载业务逻辑，Repository 只负责 SQLite 读写。

- **AI Assistant**：通过 Tool Registry 调用 Service，不能绕过命令策略、配置策略或其他本地安全检查。

应用启动时会加载 `.env`、执行 SQLite migration，然后装配各层依赖并启动 Flet 界面。只有用户真正请求启动 Minecraft 服务器时，应用才会检查并补齐 `server.properties` 中的 RCON 配置。

### 应用与界面

- **Python / Flet**：实现确定性运维服务、桌面界面和本地 Web 模式。

- **psutil**：采集系统和 Minecraft 进程树指标。

- **python-dotenv**：加载本地环境变量。

### 数据与 AI

- **SQLite**：保存运行数据、聊天记录和审计轨迹，并启用 WAL、外键约束与写入超时。

- **OpenAI-compatible SDK**：实现 Qwen、DeepSeek 等模型的 Function Calling 与流式响应。

- **dulwich**：提供配置快照的本地 Git 版本管理。

### 测试

使用 `pytest` 和 `pytest-cov` 进行单元测试、集成测试及覆盖率检查。测试不依赖真实 Minecraft 服务器或模型 API。

MVP 不使用 LangChain。当前需求由 OpenAI-compatible SDK、本地 Tool Registry 和 SQLite 会话记忆完成。

## 快速开始

### macOS / Linux

```bash
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements.txt
python -m src.main
```

### Windows PowerShell

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -m src.main
```

### 首次启动

- 从 `.env.example` 创建 `.env`，生成随机 RCON 密码并计算推荐内存。

- 执行数据库 migration，打开可跳过的基础设置窗口。

- 检测服务器目录、启动脚本、服务端 jar 和 Java 环境。

你仍需自行准备并选择 Minecraft Java 服务端文件。AI 为可选功能；填写服务商的 API Key 和 Base URL 后，应用会获取可用模型。

### Minecraft 服务端

- `MC_SERVER_DIR`：Minecraft 服务端所在目录。

- `MC_SERVER_JAR`：服务端核心文件名。

- `MC_JAVA_PATH`：用于启动服务端的 Java。

将服务端核心放到 `MC_SERVER_DIR` 指定的目录，并确保文件名与 `MC_SERVER_JAR` 一致。

### RCON 与安全

`MC_RCON_PASSWORD` 会在首次启动时自动生成，也可以在 `.env` 中手动覆盖。应用只会在用户请求启动服务器时，将 RCON 配置写入 `server.properties`。

请勿将真实 API Key、RCON 密码或 `.env` 提交到仓库。

### AI 服务商

DeepSeek 和 Qwen 只需配置其中一个 API Key。其他服务商需要提供兼容 OpenAI 的模型列表与聊天接口。

设置页可以添加多个服务商、选择常用模型，并管理游戏内 `@AI` 的启用状态、开放范围和玩家名单。

### 本地 Web 模式

默认以 Flet 桌面窗口启动。如需使用本地 Web 模式，在 `.env` 中设置：

```dotenv
FLET_RUN_VIEW=web
FLET_SERVER_HOST=127.0.0.1
FLET_SERVER_PORT=8550
```

Web 模式默认只适合本机使用。在没有认证、HTTPS、访问控制和网络防护时，不要将其直接暴露到公网。

### 准备环境

1. 运行 `python -m src.main`，完成基础设置。

2. 将服务端文件放入 `mc_server/`，或选择已有服务端目录。

3. 检查自动识别的 Java、启动脚本和内存建议。

### 日常运维

1. 在顶部服务器控制区启动服务器并观察运行状态。

2. 使用玩家面板、文件工作台、日志筛选和命令控制台。

3. 对高风险命令和配置变更检查风险等级与 diff，再确认或拒绝。

### 使用 AI

1. 在设置中配置模型服务商和模型。

2. 使用运维助手查询状态、解释日志或生成配置提案。

3. 如需游戏内答疑，启用游戏内 AI 并配置玩家访问权限。

### 运行测试

```bash
python -m pytest
python -m pytest --cov=src --cov-report=term-missing
```

## 常见问题

### 这个项目会提供 Minecraft 服务端核心吗？

不会。你需要自行准备原版、Mod 或插件服务端，并遵守对应项目和发行渠道的许可。

### 不配置 AI 能用吗？

可以。服务器启停、日志、玩家、文件、配置和命令等大部分本地管理功能仍可使用；只有 AI 对话和自然语言解释等能力需要模型服务。

### 玩家如何在游戏里使用 AI？

先在设置中配置可用模型并启用“游戏内 `@AI`”，然后玩家在聊天中输入 `@AI 问题`。管理员可以限制使用范围或通过名单调整具体玩家的权限。

该入口不能执行服务器命令或修改配置。

### 可以直接暴露到公网吗？

不建议。当前版本主要面向本地使用，Web 模式在没有认证、HTTPS、访问控制和网络防护时不应开放到公网。

### 会自动删除我的 Mod 或插件吗？

不会。当前版本只生成诊断结果和修复草案，不会自动删除、移动、禁用、替换或修改 jar 文件。

### 支持基岩版吗？

当前主要面向 Minecraft Java 版，不以基岩版服务端为支持目标。

### 能保证找出所有 Mod 或插件冲突吗？

不能。体检系统会根据可读取的元数据、依赖、服务端类型和日志提供线索，部分冲突仍需要结合具体整合包、配置和复现过程人工判断。

## 参与贡献

### 可以提供什么

- Bug 反馈、可复现步骤和启动失败日志样本。

- Mod / 插件冲突案例及其解决过程。

- 新手使用反馈、README 和其他文档改进。

提交日志或配置片段前，请先删除 IP、Token、RCON 密码、API Key 和玩家隐私信息。

### 代码约定

- 保持 `UI → Interface → Service → Repository → SQLite` 的分层边界。

- 确定性能力优先使用普通 Python 服务实现，AI 工具只能调用 Service 层。

- 新增命令或配置写入能力时，同步考虑策略校验、脱敏、审计和测试。

测试必须能够在没有真实 Minecraft 服务器和模型 API 的环境中运行。

### 提交前检查

```bash
python -m pytest
python -m pytest --cov=src --cov-report=term-missing
```

不要提交 `.env`、API Key、RCON 密码、SQLite 数据库、世界文件或其他运行时数据。
