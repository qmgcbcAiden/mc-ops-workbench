# MC 运维工作台

> 面向 Minecraft 新手服主的本地 AI 辅助工具：让开服、看日志、管理玩家、改配置和排查 Mod / 插件问题尽量更安全、更好懂。

## 项目简介

MC 运维工作台是一款帮助新手管理 Minecraft Java 服务器的本地运维工具，可使用桌面窗口，也可切换到默认仅供本机访问的 Web 模式。

如果你只是想和朋友联机，却被 Java 版本、启动脚本、黑色命令行、报错日志和各种配置文件劝退，这个项目就是为你准备的。

你可以在一个界面里启动和关闭服务器、查看谁在线、观察电脑占用、阅读日志、管理玩家和修改常用设置。遇到看不懂的报错时，可以让 AI 结合相关日志给出解释；配置 AI 后，游戏内玩家也可以通过 `@AI` 获得简短答疑。

AI 不是必需品。即使不配置任何 AI，也可以正常使用大部分服务器管理功能。

## 核心亮点

- **真正面向新手**：重点解决“想和朋友联机，但不会开服、不会看日志”的问题，不是专业商业服主面板。

- **AI 完全可选**：不配置 AI，也能使用大部分本地服务器管理、玩家、日志、文件和配置功能。

- **查询真实状态**：AI 通过受控工具读取服务器状态、玩家和日志，不会只凭聊天内容猜答案。

- **危险操作需要确认**：高风险命令不会悄悄执行，最终决定权始终在用户手中。

- **配置修改可以回看**：修改前可查看差异，修改过程有记录，并支持版本历史与回滚。

- **诊断尽量有依据**：Mod / 插件问题会结合本地文件信息、依赖、服务端日志和规则判断，而不是单纯让模型猜。

## 为什么做这个项目

很多人想和朋友一起玩 Minecraft，却卡在了开服的第一步：

- 不知道该安装哪个 Java。

- 双击启动脚本后窗口一闪而过，不知道哪里出错了。

- 日志满屏英文，看到了 `ERROR` 也不知道该怎么办。

- 想修改人数、难度或正版验证，却找不到对应设置。

- 想添加 Mod 或插件，又担心版本不匹配、服务器无法启动。

- 想给朋友管理员权限，却害怕输错命令或改坏文件。

传统开服往往要求你同时理解命令行、配置文件、端口、Java 和服务端日志。对只想和朋友联机的人来说，这个门槛没有必要这么高。

这个项目希望把常见操作放进一个看得懂的界面，并在容易出错的地方提供提示、确认和恢复办法。你不需要先成为服务器运维专家，才能拥有自己的 Minecraft 服务器。

## 项目定位

这个项目主要面向：

- 第一次尝试开服的 Minecraft 玩家。

- 想和同学、朋友联机，但不知道如何搭建服务器的人。

- 预算有限，希望用自己的电脑开一个小型服务器的学生或个人服主。

- 已经有服务端文件，但不熟悉命令行、日志和配置文件的人。

### 它是

- 面向 Minecraft 新手服主的 AI 辅助开服与运维工具。

- 在自己电脑上运行的服务器工作台。

- 帮助理解启动失败和报错信息的日志助手。

- 根据本地证据检查 Mod / 插件问题的体检工具。

- 支持配置编辑、修改记录、版本历史和回滚的管理工具。

- 提供启停、启动脚本、玩家、监控和命令功能的基础服务器控制台。

- 为游戏内玩家提供受限短对话的可选 AI 助手。

### 它不是

- 专业商业服主面板。

- Pterodactyl 或其他成熟托管面板的替代品。

- 多节点服务器集群管理系统。

- 服务器租赁或全自动托管平台。

- 能自动解决所有 Mod / 插件冲突的万能工具。

目前它是一个仍在开发中的早期版本，主要用于管理你自己电脑上的一个 Minecraft Java 服务器。仓库不会提供开服所需的服务端程序（例如 `server.jar`）；你仍然需要自行准备想要使用的原版、Mod 或插件服务端，并遵守对应许可。

## 功能特性

### 服务器启动与运行

- **用按钮控制服务器**：启动、停止或重启服务器，不必一直盯着命令行窗口。

- **兼容常见启动脚本**：自动识别当前平台可用的 Shell、Batch 等 Minecraft 启动脚本；没有脚本时会生成受管理的启动脚本。

- **尽量保持无界面运行**：启动时确保带上 `nogui`；需要改写简单的自定义脚本时会先创建备份，无法安全处理复杂脚本时则取消启动并说明原因。

- **快速发现 Java 问题**：检查 Java 版本是否适合当前服务端；缺少可用版本时，可以为本项目单独安装一份便携 Java。

- **一眼看懂运行状态**：查看服务器状态、PID、当前在线人数，以及系统和服务端进程树的 CPU、内存占用。

### 玩家、日志与命令

- **查看和管理玩家**：查看在线玩家、管理员和封禁名单，处理管理员权限（OP）、封禁、解封等常见操作。

- **实时查看服务器日志**：日志会随着服务器运行自动更新，可以搜索和筛选重要内容。

- **让 AI 帮你看报错**：将相关日志片段交给 AI，解释可能的原因和处理方向，而不是上传整份日志。

- **支持游戏内 `@AI`**：玩家可以直接在 Minecraft 聊天中提问，回复会回到游戏内；管理员可控制是否启用、开放给所有玩家还是仅管理员，并配置名单规则。

- **更安全地输入命令**：危险命令会在执行前再次确认，明显不是 Minecraft 命令的内容会被拒绝。

### 文件与配置

- **在界面中修改配置**：浏览和编辑服务端允许修改的文本配置，不必在多个文件夹之间来回寻找。

- **提供代码式文件工作台**：预览和编辑常见配置、文本及启动脚本，并为支持的格式提供语法高亮和保守格式化。

- **改错后可以回看和恢复**：重要配置修改会保留历史，可以比较前后差异并回到之前的版本。

- **先审查再应用配置提案**：默认会先展示配置修改的风险、原因和差异，由用户确认后再写入；自主配置循环需要单独启用并受风险阈值约束。

### AI 助手与诊断

- **检查 Mod 和插件问题**：扫描已安装内容，帮助发现缺少依赖、版本不匹配和可能的冲突。

- **直接用自然语言提问**：例如“现在有谁在线”“为什么服务器启动失败”“帮我把最大人数改成 10”。

- **支持多个模型服务商**：内置 DeepSeek、Qwen 配置，也可添加提供 OpenAI 兼容接口的服务商，并从接口动态获取可用模型。

- **保留重要操作记录**：命令、配置修改、聊天和工具操作都会留下记录，方便之后检查发生了什么。

## 启动脚本与 Java

应用会优先寻找当前操作系统可用、且内容看起来确实用于启动 Minecraft 的脚本。常见的 `run.sh`、`start.sh`、`server.bat`、`start_server.cmd` 等脚本可以直接参与启动；如果没有可用脚本，应用会根据当前 Java、内存和服务端 jar 设置生成受管理的启动脚本。

为避免意外弹出服务端 GUI，启动流程会确保使用 `nogui`。对于能够安全识别的简单自定义脚本，应用会先备份原文件，再补充所需参数；如果脚本过于复杂，无法确认修改是否安全，应用会停止启动并保留原文件。

Java 检测会结合服务端信息判断所需版本，优先使用已有环境；找不到合适版本时，可按设置下载项目内独立的 Temurin Java，不必替换系统 Java。

## 游戏内 `@AI`

配置好模型服务并启用游戏内 AI 后，玩家可以直接在聊天中输入 `@AI 这个附魔有什么用？`。这条消息会在服务器日志中表现为类似 `<Steve> @AI 这个附魔有什么用？` 的内容，应用识别请求后，通过模型生成短回复，再由受控的服务器命令通道发回游戏。

游戏内 AI 只用于闲聊、游戏机制答疑和简短建议，不会执行服务器命令、修改配置或处理运维操作。每位玩家使用独立且有长度和时效限制的短上下文，同时带有冷却、队列和回复长度限制。

管理员可以在设置中关闭该功能、限制为仅管理员可用，或通过名单规则调整具体玩家的访问权限。游戏内对话与对应模型调用也会进入本地审计记录。

## Mod / 插件体检系统

对新手来说，Mod 或插件装错位置、版本不匹配和缺少依赖，往往只会表现为“服务器打不开”。体检系统会尝试先从本地文件和日志中寻找原因，再给出尽量具体的说明。

它目前可以检查：

- 扫描 `mods/*.jar` 和 `plugins/*.jar`，读取其中可识别的名称、版本、加载器和依赖信息。

- 判断 Mod 是否误放进 `plugins/`，或插件是否误放进 `mods/`。

- 检查 Fabric、Forge、NeoForge、Paper 等服务端类型与组件加载方式是否匹配。

- 发现同一组件重复安装，或多个版本同时存在。

- 查找组件声明中缺少的必需依赖。

- 根据可获得的信息检查 Minecraft 版本是否可能不兼容。

- 从日志中识别插件加载失败、Mixin 错误、缺少类、缺少方法和依赖异常等常见问题。

诊断结果会尽量说明证据来自本地元数据、依赖关系、在线元数据还是运行日志，并给出建议动作。当前版本默认只生成修复草案，不会直接删除、移动、禁用、替换或修改你的 jar 文件。

诊断和修复建议不可能覆盖所有整合包与插件组合。处理文件前请先备份服务端，重要操作仍应由你确认。

## 为什么不是简单套壳 AI 对话

它不是一个只能陪你聊天、然后让你自己照着教程操作的机器人。

- **没有 AI 也能管理服务器**：启动服务器、查看玩家、监控占用、阅读日志和执行命令都由本地功能完成。

- **AI 查询的是真实状态**：当你问“谁在线”时，程序会查询服务器，而不是让 AI 猜一个答案。

- **AI 不能随意操作电脑**：它只能使用项目事先准备好的服务器管理功能，不能自己运行系统命令或翻看任意文件。

- **危险操作由你做最终决定**：例如封禁、给予管理员权限或停止服务器，执行前会要求你明确确认。

- **修改配置前先给你看**：程序会展示准备修改的内容和前后变化，你确认后才会真正保存。

- **不会把整份日志直接扔给 AI**：程序会先筛选相关内容，减少无关信息，也降低隐私和使用成本。

- **游戏内 AI 不具备运维权限**：玩家的 `@AI` 请求使用独立的受限提示词和短上下文，只回答普通问题，不执行命令或修改服务器。

- **出问题后有记录可查**：AI 调用了什么功能、执行了什么命令、修改了什么配置，都能留下记录。

简单来说：AI 负责听懂你的问题、解释报错和给出建议；真正控制服务器的是有明确规则和安全检查的本地程序。

## 工作原理

```text
UI (Flet)
    |
    v
Interface
    |
    v
Service -------------------+
    |                       |
    v                       |
Repository                  |
    |                       |
    v                       |
SQLite                      |
                            |
AI Assistant -> Tool Registry
                    |
                    +------> Service
```

- **UI** 只负责展示和交互，不直接访问数据库、AI SDK、RCON 或服务端文件。

- **Interface** 为 UI 提供稳定、轻量的调用门面。

- **Service** 承载玩家、日志、指标、命令、配置、Java、Addon、游戏内 AI 和聊天编排等业务逻辑。

- **Repository** 只负责 SQLite 读写，不做业务判断。

- **AI Assistant** 通过 Tool Registry 调用 Service，不能绕过本地安全策略。

应用启动时会加载 `.env`、执行 SQLite migration，然后装配各层依赖并启动 Flet 界面。只有当用户真正请求启动 Minecraft 服务器时，应用才会检查并补齐 `server.properties` 中的 RCON 配置。SQLite 使用 WAL、外键约束和写入超时配置保存运行记录。

## 技术栈

- **Python**：应用与确定性运维服务

- **Flet**：桌面及本地 Web UI

- **SQLite**：运行数据与审计记录持久化

- **OpenAI-compatible SDK**：Qwen、DeepSeek 等模型的 Function Calling 与流式响应

- **psutil**：系统和 Minecraft 进程树指标采集

- **dulwich**：配置快照的本地 Git 版本管理

- **python-dotenv**：本地环境变量加载

- **pytest / pytest-cov**：单元测试、集成测试与覆盖率检查

MVP 不使用 LangChain。当前需求由 OpenAI-compatible SDK、本地 Tool Registry 和 SQLite 会话记忆完成。

## 快速开始

### 最短启动流程

macOS / Linux：

```bash
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements.txt
python -m src.main
```

Windows PowerShell：

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -m src.main
```

首次启动会自动：

- 从 `.env.example` 创建 `.env`，并生成随机 RCON 密码。

- 执行数据库 migration。

- 打开可跳过的基础设置窗口。

- 检测服务器目录、服务端启动文件、Java 和推荐内存。

你仍需自行准备并选择 Minecraft Java 服务端文件。AI 为可选功能；填写服务商的 API Key 和 Base URL 后，应用会自动获取可用模型。

### 详细配置

准备条件：

- 可用的 Python 环境。

- 一个自行获取并同意其许可条款的 Minecraft Java 服务端核心。

- RCON 密码会在首次启动时自动生成，也可在 `.env` 中手动覆盖。

- AI API Key 为可选项；不配置时仍可使用本地运维功能。

- DeepSeek 和 Qwen 只需配置其中一个 API Key；应用会自动选择已配置的服务商。

- 其它服务商需要提供 OpenAI 兼容接口，设置页可添加多个服务商。

- 可用模型通过服务商的 OpenAI 兼容模型列表接口动态获取；模型太多时，可在设置页只启用常用模型。

大部分用户可以通过顶部启动按钮旁的设置入口完成配置。基础设置会展示已配置的 AI 服务商、环境变量名称、API Key、Base URL、服务器目录和最大内存；检测失败时再展开手动调整 jar 或 Java 路径。

设置页还可以管理游戏内 `@AI` 的启用状态、默认开放范围和玩家名单规则。

如需高级配置，可以继续直接编辑 `.env`：

- `MC_SERVER_DIR`：Minecraft 服务端所在目录。

- `MC_SERVER_JAR`：服务端核心文件名。

- `MC_JAVA_PATH`：用于启动服务端的 Java。

- `MC_RCON_PASSWORD`：自动生成的本地 RCON 密码，不要提交到仓库。

将服务端核心放到 `MC_SERVER_DIR` 指定的目录，并确保文件名与 `MC_SERVER_JAR` 一致。服务端核心、世界、日志和运行数据不会提交到 Git。

启动应用：

```bash
python -m src.main
```

默认以 Flet 桌面窗口启动。如需使用本地 Web 模式，在 `.env` 中设置：

```dotenv
FLET_RUN_VIEW=web
FLET_SERVER_HOST=127.0.0.1
FLET_SERVER_PORT=8550
```

如需启用 AI 助手，再为所选模型提供对应的 API Key 和 OpenAI-compatible Base URL。请勿将真实密钥或 RCON 密码提交到仓库。

运行测试：

```bash
python -m pytest
```

生成覆盖率报告：

```bash
python -m pytest --cov=src --cov-report=term-missing
```

## 基本使用流程

1. 运行 `python -m src.main`；应用会自动创建 `.env` 并打开基础设置。

2. 将 Minecraft 服务端文件放入 `mc_server/`，或在设置中选择现有服务端目录。

3. 检查自动识别的 Java 和内存建议；需要 AI 时填写 API Key 与 Base URL。

4. 在顶部服务器控制区启动服务器，并观察状态、PID、CPU、内存和实时日志。

5. 使用玩家面板、文件工作台、日志筛选和命令控制台完成日常运维。

6. 对高风险命令或配置变更检查命令内容、风险等级与 diff，再选择确认、拒绝或回滚。

7. 配置 AI 后，可在运维助手中用自然语言查询状态、解释日志或生成配置提案；最终执行仍受本地策略控制。

8. 如需开放游戏内答疑，在设置中启用游戏内 AI 并配置权限；玩家随后可用 `@AI 问题` 发起短对话。

## 安全提醒

> 使用前请先备份重要的世界、配置和 Mod / 插件文件。

- 不要提交或公开 `.env`、API Key、RCON 密码、SQLite 数据库、世界文件，以及可能包含 IP 或玩家信息的日志。

- Web 模式目前主要建议在本机使用；没有认证和网络防护时，不要直接暴露到公网。

- 执行高风险命令、应用配置修改或处理 Mod / 插件修复草案前，请先确认内容并做好备份。

- AI 诊断只是辅助建议，不能保证覆盖所有服务端、整合包和插件组合，最终操作仍由用户确认。

- 项目不提供 Minecraft 服务端核心、Mod、插件或其他第三方内容，请自行获取并遵守相应许可。

## 当前状态

项目目前处于积极开发中的可运行 MVP 阶段。核心分层架构、SQLite migration、服务器生命周期管理、跨平台启动脚本、玩家与日志能力、安全命令、文件与配置工作台、配置版本、AI Function Calling、游戏内 `@AI`、Java 环境处理和 Addon 诊断均已具备实现与测试。

当前测试基线可收集近 600 个测试，覆盖服务器生命周期、启动脚本、日志、玩家、配置编辑、命令安全、AI 工具调用、游戏内 `@AI`、Java 环境处理和 Mod / 插件诊断等核心路径。

当前实现仍以本地开发和功能验证为主，接口与数据库结构可能随 MVP 迭代调整。

## 已知限制

- 当前主要面向一个本地 Minecraft 服务器实例，不支持多节点或服务器集群。

- 没有多用户登录、角色权限、租户隔离和公网部署所需的完整安全体系。

- Web 模式默认只监听 `127.0.0.1`；在没有额外认证和网络防护时不应直接暴露到公网。

- 仓库不包含 Minecraft 服务端核心、世界文件、Mod、插件或第三方内容，使用者需要自行准备并遵守相应许可。

- AI 对话、在线模型能力以及 Modrinth / CurseForge 知识增强依赖外部服务、网络和相应凭据。

- 游戏内 `@AI` 依赖服务端日志中可识别的标准玩家聊天格式，不同核心或聊天插件改写日志格式后可能需要适配。

- 不同 Minecraft 核心、Mod Loader、插件和 Java 版本组合仍可能需要手动调整。

- 自主配置修改循环默认关闭；启用前应理解自动应用阈值、验证范围和潜在风险。

- 当前仍是 MVP，尚未提供正式安装包、稳定版本承诺和自动升级机制。

## 常见问题

### 这个项目会提供 Minecraft 服务端核心吗？

不会。你需要自行准备原版、Mod 或插件服务端，并遵守对应项目和发行渠道的许可。

### 不配置 AI 能用吗？

可以。服务器启停、日志、玩家、文件、配置和命令等大部分本地管理功能仍可使用；只有 AI 对话、自然语言解释等能力需要模型服务。

### 玩家如何在游戏里使用 AI？

先在设置中配置可用模型并启用“游戏内 `@AI`”，然后玩家在聊天中输入 `@AI 问题` 即可。管理员可以限制使用范围或通过名单排除、额外允许指定玩家；该入口不能执行服务器命令或修改配置。

### 可以直接暴露到公网吗？

不建议。当前版本主要面向本地使用，Web 模式在没有认证、HTTPS、访问控制和网络防护时不应开放到公网。

### 会自动删除我的 Mod 或插件吗？

不会。当前版本只生成诊断结果和修复草案，不会自动删除、移动、禁用、替换或修改 jar 文件。

### 支持基岩版吗？

当前主要面向 Minecraft Java 版，不以基岩版服务端为支持目标。

### 能保证找出所有 Mod 或插件冲突吗？

不能。体检系统会根据能读取到的元数据、依赖、服务端类型和日志提供线索，但部分冲突仍需要结合具体整合包、配置和复现过程人工判断。
